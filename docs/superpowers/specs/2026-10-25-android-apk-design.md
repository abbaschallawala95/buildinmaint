# Android APK — Design

**Date:** 2026-10-25 · **Status:** built and installed 2026-10-26 (working on the owner's phone)

## Goal
Install Build Maintain on the owner's Android phone as a real app from a `.apk` file — own icon, full screen, no browser bar. Personal use only: **no Play Store**.

## Approach (chosen)
A **Trusted Web Activity (TWA)** generated by [PWABuilder](https://www.pwabuilder.com). The APK is a thin shell that opens the live site `https://buildinmaint.vercel.app` full-screen using Chrome's engine on the phone.

Why this one:
- The app renders on the server (Next.js server components/actions, Supabase, Prisma), so it can't be bundled into a phone app anyway — the phone must load the live site.
- Chrome-based, so login cookies, themes, and **PDF/Excel export downloads work unchanged** (a plain WebView would need extra code for downloads).
- No Android Studio, JDK or Gradle on this PC; PWABuilder builds and signs the APK online.
- Web updates pushed to Vercel appear in the app automatically — no APK rebuild for normal changes.

Rejected: Chrome "Install app" only (no `.apk` file — kept as a free fallback, same manifest); Capacitor + Android Studio (heavy toolchain, download handling code; only worth it for native features like push notifications — not needed).

## What changes

### 1. Web app (deployed via the normal push to `main`)
| File | Purpose |
|---|---|
| `src/app/manifest.ts` | Web app manifest (Next.js metadata route, served at `/manifest.webmanifest`): name "Build Maintain", short name "Build Maintain", `start_url: "/"`, `display: "standalone"`, `background_color`/`theme_color` `#0F1222` (Indigo sidebar), icons below. |
| `public/icons/icon-192.png`, `icon-512.png`, `icon-maskable-512.png` | App icons made once from `src/app/icon.svg` (white building on Indigo `#5B5BD6`; the maskable one has extra padding so Android can crop it to any shape). |
| `public/.well-known/assetlinks.json` | Digital Asset Links file from PWABuilder. Proves the APK and the site belong together, which removes the browser bar. Added in a second, small commit after the APK is generated. |

- The proxy (`src/proxy.ts`) already skips `.png` files; `/manifest.webmanifest` and `/.well-known/assetlinks.json` pass through it untouched (it only redirects `/admin`, `/member`, `/login`). Must be verified as public (no login needed).
- No service worker / offline mode (YAGNI — the app needs the internet for its data). If PWABuilder ever refuses to package without one, add its basic offline-page worker then.

### 2. APK (built on pwabuilder.com, nothing installed locally)
- Package ID: `app.vercel.buildinmaint.twa`, app name "Build Maintain", launcher name "Build Maintain".
- Signing: "Create new" key. The download zip contains the `.apk`, an `.aab` (Play Store only — ignore), `signing.keystore`, `signing-key-info.txt`, and `assetlinks.json`.
- **The keystore + passwords are kept privately outside the repo** (e.g. a personal Drive folder). They are needed only to ship an APK update (new icon/name/package settings); losing them means uninstalling and reinstalling the app.

### 3. Phone install
Copy the `.apk` to the phone (WhatsApp to self / Drive / USB) → tap it → allow "Install unknown apps" for that app → if Play Protect warns, "More details → Install anyway".

## What does NOT change
App pages, data, login, roles, themes, exports — all identical to the website. No new dependencies in `package.json`. No database changes.

## Testing
- `https://buildinmaint.vercel.app/manifest.webmanifest` returns the manifest; the three icon URLs return images — all without being logged in.
- PWABuilder's report card shows the manifest as valid (no blocking errors).
- `https://buildinmaint.vercel.app/.well-known/assetlinks.json` returns the JSON publicly.
- On the phone: opens full-screen with **no URL bar**; log in; switch building/theme; download a PDF export and open it; Android back button navigates back; app shows in recent apps with its icon.

## Risks
- URL bar still visible → `assetlinks.json` missing/wrong fingerprint, or the phone cached the old check: clear the app's storage or reinstall.
- Chrome missing/disabled on the phone → TWA falls back to a custom tab (still works, shows a bar). Keep Chrome installed and updated.

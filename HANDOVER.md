# Handover

## What this is
Building/society maintenance management app. Next.js 16 (App Router) + Prisma 7 + Supabase Auth, Postgres via Supabase.

## Stack
- Next.js 16, React 19, Tailwind 4, shadcn/ui components (`src/components/ui`)
- Prisma 7 (`prisma/schema.prisma`), generated client output to `src/generated/prisma` (gitignored — regenerated via `postinstall` script)
- Supabase for auth (`src/lib/supabase/`); `Profile` model mirrors `auth.users`
- **Multi-building/multi-tenant** (added 2026-08-07): every `Profile` optionally belongs to a `Building`. Roles: `SUPER_ADMIN` (no building, cross-building via a switcher), `BUILDING_ADMIN` (locked to one building), `MEMBER` (locked to one building) — both admin roles route to `/admin`, `MEMBER` to `/member`, from `src/app/page.tsx`. See `src/lib/building-context.ts` for how every admin page/action resolves "which building am I operating on".

## Features built (as of 2026-07-30, updated through 2026-09-02)
- **Super Admin**: `/admin/buildings` — full CRUD for buildings (create/rename/delete, delete requires typing the exact building name) and their one admin each (create/edit/reset-password/remove, admin details tucked into a dropdown per building row). A sidebar building-switcher (cookie-backed) lets Super Admin act as admin for whichever building is selected — same `/admin/**` pages as `BUILDING_ADMIN`, just building-scoped by context instead of by profile.
- **Admin** (Super Admin acting on a building, or that building's `BUILDING_ADMIN`): floors/flats (with `FlatMaintenanceRate` history — a rate change applies from its "Effective From" month, which can be back-dated to correct a past rate), members (users), monthly payments + per-flat additional charges + previous-year dues entry, carried-forward due schedule per flat since Jan 2026, expenses (with categories — add/rename/delete via the Categories dialog; a category in use can't be deleted), electricity bills (lift/common area), cleaners (name/salary, monthly paid/unpaid tracking — see below), settings (building name, opening balance, member financial visibility toggle, members-can-browse-all-months toggle), audit log (paged, 50 per page), PDF/Excel exports (`/admin/export` — Monthly Report and Total Dues Report, see below)
- **Member**: dashboard — own flat, full month-by-month due schedule since Jan 2026 with a year filter and total dues, additional charges, optional building-wide financial overview with optional all-months browsing (both gated by settings toggles)
- **Auth**: `/login` via Supabase. `Profile.mustChangePassword` forces a blocking "set a new password" dialog on first login after account creation or after a super-admin/admin password reset — see 2026-09-01 session log.
- **Nav**: `src/components/nav-shell.tsx` — off-canvas drawer sidebar below `md` breakpoint (hamburger button, backdrop, closes when a menu link is tapped), static sidebar on desktop. Drives both `/admin` and `/member` layouts; also renders the Super Admin building switcher.
- **Cleaners** (`/admin/cleaners`): `Cleaner` (name, current monthly salary) + `CleanerSalaryHistory` (rate by effective month — a change applies from its "Salary Effective From" month, which can be back-dated; earlier months keep the old rate) + `CleanerPayment` (one row per cleaner/month) + `CleanerPaymentEntry` (many payments per month, so salary can be paid in installments; status Unpaid/Partial/Paid is derived from paid-vs-due). An advance is just an entry recorded against a future month via the existing month/year filter. All `CleanerPaymentEntry` rows feed `totalOutgoing`/closing balance in `src/lib/finance.ts` alongside expenses and electricity bills.
- **Exports** (`/admin/export`): Monthly Report (income/expense summary, per-flat maintenance status, transactions for a picked month) and Total Dues Report (every flat's accumulated dues + unpaid-months list/count + unpaid charges), each downloadable as PDF (`pdf-lib`) or Excel (`exceljs`) via plain GET routes under `/api/admin/export/*`.

No dedicated in-repo plan/TODO doc exists — DB migration names double as a rough changelog (`init` → `stage2_expenses_bills_settings` → `add_cleaners`).

### Env vars (set in Vercel project settings + local `.env`, never commit values)
- `DATABASE_URL` — Supabase Postgres. **Two different connections in use on purpose:**
  - Local `.env` (dev machine): session-mode pooler, port `5432` — required for `prisma migrate dev` (transaction-mode pooler doesn't support the advisory locks migrations need).
  - Vercel Production + Preview: transaction-mode pooler, port `6543` with `?pgbouncer=true` — required for serverless runtime (see "Known fix" below). Vercel never runs migrations at build time (`postinstall` only runs `prisma generate`), so this split is safe.
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_SECRET_KEY`

### Known fixes already applied
- Vercel build initially failed with `module-not-found` on `@/generated/prisma/client` because the generated client is gitignored and nothing ran `prisma generate` in a fresh checkout. Fixed by adding `"postinstall": "prisma generate"` to `package.json`.
- Production started throwing "server error" on refresh: Supabase session-mode pooler caps at 15 clients, and each serverless invocation opened its own Prisma connection, exhausting it (`EMAXCONNSESSION`, confirmed via `vercel logs`). Fixed by switching Vercel's `DATABASE_URL` to the port-6543 transaction-mode pooler (`vercel env update DATABASE_URL production/preview --value ...`), then `vercel deploy --prod`.
